# LLM / Agent 类项目规范

> 2026-10-11 从原《代码规范》架构 §10 拆出；仅用于对应项目，不作为所有语言的默认规则。
> 原厂商行为描述按原文迁移；具体厂商接口仍按原条文要求查其文档。

> 面向"调用大模型 + 工具循环"这一**类**项目（非单一项目）。

**模型适配层返回契约**（多家厂商统一成一个形状）：

统一字段为 `content`、`reasoning`、`usage`、`tool_calls`；原 Python 表示方式见
[Python 模型适配契约](../语言规范/Python/代码规范.md#llm--agent-接口的-python-表示)。

- 🟡 `arguments` 从 API 拿到时是 **JSON 字符串**，不是对象——先按对应语言解析 JSON；原 Python 写法见上述语言规范。
- 🟡 `usage.completion_tokens` 通常**已含** reasoning tokens，统计成本别二次相加。

**工具消息契约**（违反任何一条都可能被 API 拒绝）：

1. 🔴 assistant 消息必须**原样回存**（含 tool_calls 字段）——缺了模型就"忘了"自己调过工具；
2. 🔴 每个 tool_call 必须紧跟一条 `{"role":"tool","tool_call_id":id,"content":文本}`；
3. 🔴 并行多个 tool_calls 必须**全部执行、全部回复**；
4. 🟡 reasoning 字段：不同厂商的回传规则不同（有的必传、有的不能传），按厂商文档分支处理；
5. 🟡 流式 tool_calls 分片：`index` 分槽、id / name 只在首片、arguments 用 `+=` 累加。

**数据格式（人机一致）**：

- 🔴 人类可手改的库（记忆 / 词条）用**一行一条**的纯文本格式，程序只认固定行首标记；
  解析规则出现在多处时，**改格式必须同时改**；
- 🔴 过程流水（聊天记录）与沉淀事实（记忆库）**物理分开**；增删改查序号**从 1 开始**。
