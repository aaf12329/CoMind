### 🔴 工作准则：不看 Token 账单，只看协作效率

> 所有者原话（2026-10-20）：**"我不需要 Token 账单，我只看协作效率。"**

- **考核项是效率，不是花费**：token 数、调用次数、上下文长度都**不作为评价指标**；
  评价的是同一个活**用几下干完**——几次往返、几个 Agent、多长时间、返工几次。
- **该花的必须花**：该查证的查证、该跑的测试跑、该派的子代理派、该写的证据写。
  不得拿"省 token / 省上下文 / 省调用"当理由少做一步。
- **该省的是往返，不是 token**：一次问清 > 三次来回；一个肥的子代理 > 三个碎的子代理；
  一句话能说清的结论不要写三页。省下来的是所有者的时间与注意力。
- **该并行就并行，该串行就串行**：并行不增加主代理的上下文压力，
  但冲突面、等待与返工都是效率损失——判据见 [`00_子代理与效率.md`](00_子代理与效率.md) §1。
- **不许为花钱凑数**：也不准为了"显得在忙"堆无用工作、重复验证、无意义扩写。
- **唯一标准**：**结果对不对 + 过程顺不顺**。判断依据是**真实验证证据**（跑过的测试、
  真实命令输出、可复核的 diff），不是"我做完了"。
- 🟡 这条不改变权限规则：**不计成本 ≠ 不受权限约束**，§02 与子代理规则照旧。

## 02 · Git 分工与 push 权限

> 🔴 **本节是全库最高优先级的权限条款**：不论哪个项目、哪种协作方案，都按本节执行。
>
> 🔴 **一切授权一次有效**：所有者给出的每一条授权指令（`push`、开子代理、任何超出默认
> 权限的操作）**都只用一次**——干完即失效，**不得续用、不得延展、不得类推到下一次**，
> 也不得转授。要再干，**重新申请**。授权没给全的，就当没给。

### 02.1 🔴 AI 的 git 动作清单（能做什么 / 不能做什么）

#### ✅ 可以自由做（只读，不改变历史）

`git status` / `diff` / `log` / `show` / `blame` / `branch --list` / `stash list`
—— 随时用，先看清楚再动手。

#### 🟢 可以做，但要守规矩

| 动作 | 规矩 |
|---|---|
| `git add` / `git commit` | AI 做。**按名挑文件**；🔴 **禁止 `git add -A` / `git add .`** 把所有者未提交的改动卷进来 |
| 新建分支 | 🟡 先在说明里讲一句，再建 |
| `git stash` | 🟡 只用于自己造成的中断，用完必须 `stash pop` 复原；🔴 不许 stash 别人的改动 |

#### 🔴 必须授权

| 动作 | 规矩 |
|---|---|
| `git push` | 🔴 **只有所有者本人**；AI 默认没有权限，授权**一次一用**（§02.2） |
| 改 remote / 发 PR / merge / 删分支 | 🔴 需所有者同意 |

#### ⛔ 永远不做（任何授权都不包含）

| 动作 | 为什么 |
|---|---|
| `git push --force` / `--force-with-lease` | 会覆盖远端历史 |
| `git reset --hard` / `git checkout -- <file>` / `git clean -fd` | 会丢未提交的改动（含所有者或子代理的工作） |
| `git rebase` / `commit --amend` **已推送的提交** | 等于改写公共历史 |
| 把别人未提交的改动带进自己的提交 | 典型事故：`git add -A` 把所有者写了一半的文件一起提交了 |

### 02.2 🔴 push 授权：一次一用

- **默认状态**：AI 改完**停在 `commit`**，等所有者自己推。
- **人类可以授权**：所有者说"这次 push 权限给你"即生效，AI 才可以推。
- 🔴 **一次授权只能用一次**：
  - 只对**当次那一批提交**有效，推完**立即失效**；
  - 不延展到之后的任何改动；
  - 不跨仓库、不跨分支；
  - 不得转授给子代理或别的 Agent；
  - AI 不能自行"续用"上一次的授权。
- **要再推，必须重新获得授权。**
- 🟡 授权状态不明时，**默认按"没有授权"处理**——先问，不要试着推。
- 🟡 AI 申请授权的标准说法：
  `已完成 N 个提交（<短 hash 列表>），是否允许 push？仅本次。`

### 02.3 提交侧的两种方案（任选其一，写明默认）

**方案一 · AI 提交** 🟡（推荐默认）
- 日常 `git add` + `git commit` 由 AI 执行；
- 🔴 `git push` 按 §02.1 / §02.2 执行——AI 一律等授权，推完即失效。

**方案二 · 指令块审查** 🟡
- AI 把 add/commit/push 整理成可粘贴的命令块，所有者审查后自己执行；
- 例外：所有者明确说"你 push 一下"时直接执行——但同样**一次一用**。

> 演进记录写成 `日期 ──▶ 方案 ──▶ 一句话变化`；旧方案标注"已被取代的部分"，
> 仍有效的条目（先声明、代码带注释、README 同步）单独保留。

### 02.4 🔴 子代理：零 git 操作

子代理**一个 git 命令都不许执行**——`add` / `commit` / `push` / 建分支 / 改 remote / stash 全不行。

理由：多个代理并发各自提交，冲突与历史污染主代理收不了口。

- 子代理只负责**改文件**，改完把结果交回主代理；
- **主代理收口**：`git status` → 逐个 `git diff` 验真身 → 按名 `add` → 一个逻辑单元一次提交；
- 🔴 主代理**不采信**子代理"我做完了 / 已经全绿了"的自述，测试自己再跑一遍。

（子代理开不开、开几个，见 `00_子代理与效率.md`。）

## 03 · 提交信息

> **核心原则**：中英双语、中文在前；一段话说清：做了什么 + 怎么验证的 + 影响哪些文档。

**格式 A · 单行双语式** 🟡（轻量仓库，`CH:` / `EN:` 各一行）

```text
CH:新增配置导出功能（默认关闭），README 同步更新
EN:Add config export (off by default); README updated accordingly
```

**格式 B · 段落式** ⭐ 推荐（新提交向此格式靠拢）：标题 + 中英两组 bullets。

```text
功能：数据管道断点续跑 + 进度落盘

- 每个 stage 完成后写 checkpoint.json，中断后跳过已完成阶段
- 抽样验证：3 次中断重启，结果与一次跑完一致
- README 工作流一节同步更新

Feature: resumable data pipeline with progress on disk

- checkpoint.json written after each stage; restarts skip finished stages
- Verified by 3 interrupt-restart runs, output identical to a single run
- README workflow section updated
```

**格式 C · 序号式** 🟢、**格式 D · 竖线分隔式** 🟢：分别适合教学/刷题仓库与
标题一行中英竖线分隔（正文两个 `-m` 分写）——两种备选，按需取用。

**类型前缀** 🟡：`文档：`　`规范：`　`功能：`　`修复：`　`整理：`　`重构：`
**特殊约定** 🟡：`历史版本：` 前缀 = 旧代码快照存档；tag 命名 `v主.次` / `功能词-v1`。
**历史教训** 🟡：标题 ≤72 字符（细节放正文）；前缀大小写统一；多仓库风格向格式 B 收敛。

- [ ] 5️⃣ 有了**新的实测结果或图表**？→ `<docs/ 或等价的归档目录>` 存档

## 07 · 仓库卫生

### 🔴 信息上传边界（所有 Agent、所有话题适用）

**严禁上传任何具体政治内容；可以在去除现实政治指向后进行抽象建模。** 本条适用于主代理、子代理及后续接手的 Agent，覆盖所有项目、所有话题，不限于写文章或 Git 提交。

- **禁止上传的内容**：涉及具体政治人物、组织、事件或可识别现实政治对象的原文、观点及分析。正文、附件、截图、音视频、摘要、文件名、日志与提交信息均须检查。
- **上传包括**：向云端模型或 API 发送上下文、向搜索引擎提交查询、向外部工具或服务传输文件、跨会话或跨 Agent 转发，以及推送到公开或私有远端仓库。不能以“只给另一个 Agent 看”或“私有仓库”为例外。
- **允许的抽象建模**：仅保留一般变量、约束、资源流、反馈、纠错与问责等结构，使用无现实对应的主体和情境。仅替换姓名、使用代号，或保留足以反推具体对象的时间地点、独特细节和映射表，不算完成抽象。
- **先在本地筛选，再决定是否传输**：不得先把原文、截图或带具体政治内容的工具输出送入云端，再要求模型脱敏。无法确认已去除现实指向时，保留本地并跳过传输；可继续处理已确认符合边界的抽象部分。
- **接手新设备或输入环境变化时**：先只读检查本机已安装、已启用的输入法，区分国产第三方输入法与系统自带中文输入法。记录检查范围与不确定性；不因装有某输入法就断言发生上传，也不因未发现国产输入法就认定内容不会外传。安装、卸载或改动输入法设置另按用户指令执行。
- **执行边界**：本条约束 Agent 的信息传输行为，不代表已经控制输入法或其他应用的网络行为。新增规则不等于获准删除既有文章、改写 Git 历史或再次发布历史内容；处理存量资料须另按用户指定范围进行。

**Applies to every agent and topic:** never transmit concrete political content. Abstract modeling is allowed only after removing identifiable real-world political references locally. This covers model context, searches, external tools, agent handoffs, and public or private remote repositories. Input-method checks do not relax this boundary.

### 🔴 永不入库

- 密钥与凭据（`.env`、API key）
- 虚拟环境（`myvenv/`、`venv/`、`.conda/`）
- 缓存与生成物（`__pycache__/`、构建输出）、`node_modules/`
- 硬件照片等临时资料
- **数据文件**——聊天记录、数据集原始文件（教训：某历史存档仓库把聊天记录
  入库，单几次提交 **+43 万行**）

### 🔴 身份信息过滤（提交与文件内容）

- **提交信息与提交的文件内容中过滤所有者身份信息**——真实姓名、学校/单位、
  地理位置、联系方式、健康状况等；
- 确需写入时**先征得所有者同意**（默认按"不写"处理）；
- 同理适用于：对外分享的文档、截图、日志、演示材料；
- 例外：所有者明确要求写入的内容（如项目署名、致谢）。

**Filter identity info out of commits and repos** — real name, school/employer,
location, contact, health status — in both commit messages and committed file
contents; ask the owner first if it seems necessary. Applies to shared docs,
screenshots and logs too.

### 🟡 过滤标记约定（非通用文件）

- 仓库中若混入**非通用文件**（如个人画像、私有偏好），在文件顶部加一行
  **【请过滤本文件】** 标记；
- 该标记的含义：分享仓库、批量处理、生成公开内容时**跳过此文件**；
- 正常阅读**跳过标记行即可，无需删除**；**是否删除标记行是所有者的个人选择
  （有明确需要时才删，AI 不代删）**。

**Filter-marker convention** — mark non-generic files (personal profiles, private
preferences) with a 【请过滤本文件】 line at the top: skip them when sharing,
bulk-processing or publishing; when reading, skip the marker line — whether to
delete it is the owner's call (delete only when explicitly needed; AI never
deletes it on its own).

### 🟡 选择性入库（大文件）

| 入库 ✅ | 不入库 ❌ |
|---|---|
| 交付性产物（克隆即用的最终权重/成品，单个几 MB 级） | 训练原始输出（`runs/`、checkpoint）——README 记路径即可 |

### 🟡 磁盘报备制度

- ≥1GB 写入/删除、跨盘操作、环境安装 → 台账文件登记；
- 大动作前后**强制检查系统盘剩余容量**，报备时带数字，执行后复测记差额；
- 超大数据集放**非系统盘**的专用数据目录（连压缩包），小数据留在仓库旁。

## 10 · 文件删除与回收站

- 🔴 **删除项目文件夹之外的任何东西，必须先报备**——对话里说清楚要删什么、
  为什么删，得到确认后再动手；"先整理进知识库/仓库，再删原件"是推荐顺序。
- 🔴 **永不清空回收站**——删除一律**送回收站**，给误删留后路：
  实际命令见 [PowerShell 回收站操作示例](01_编程规范/语言规范/PowerShell/代码规范.md#回收站操作示例)。
- 🟡 删除前快速核对：目标内容是否已有归宿（并入知识库 / 仓库另有副本 / 任务产物已交付）。

**Never delete outside a project folder without reporting first** (say what and why,
get confirmation), and **never empty the Recycle Bin** — always send deletions to the
Recycle Bin (`SendToRecycleBin`), never bare `rm` outside project folders.

> 子代理规则**不再写在本文件里**——它属于"开工前"，不属于"提交"。
