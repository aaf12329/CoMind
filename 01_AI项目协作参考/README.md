## 一、干活三步，按顺序走

每个任务都按这三步走，**每一步只打开一个文件**：

| 步骤 | 什么时候 | 打开 | 你要得到什么 |
|:-:|---|---|---|
| **① 开工前** | 动手之前 | [`00_子代理与效率.md`](00_子代理与效率.md) | 算出**要开几个（0 到配额）**，要开就**申请获批**；用完即评留还是删 |
| **② 写代码** | 写/改代码时 | [`01_编程规范/代码规范.md`](01_编程规范/代码规范.md) | 按**语言**跳到对应规范 |
| **③ 提交** | `git add` / `commit` 之前 | [`02_提交与协作规范.md`](02_提交与协作规范.md) | 提交信息格式 + **git 权限边界（§02）** |

补充两页，按需取用，不进主流程：

| 场景 | 打开 |
|---|---|
| 接手一个已有项目，要写交接手册 | [`03_项目接手手册_模板与写法.md`](03_项目接手手册_模板与写法.md) |
| 查资料（GitHub 排查 / 论文获取） | [`04_资料检索/`](04_资料检索/) |
| 了解所有者的背景与偏好 | `用户个人信息参考/用户画像_协作偏好.md`（带【请过滤本文件】标记，公开材料整份跳过） |

### 一句话红线（细节在 ①③）

- 🔴 **push 只由所有者本人执行**；AI 的 git 权限**止于 `commit`**；
- 🔴 **一切授权一次有效**：推完/开完即失效，不续用、不延展、不转授；
- 🔴 **子代理权限只有两个来源**：人类直接指定，或 AI 申请并获批（**不可先斩后奏**）；配额默认 3 个；
- 🔴 **不看 Token 账单，只看协作效率**。

## 三、每条规则只有一个出处（别处只引用）

改规则时**只改出处那一份**，其余文件是引用，不需要跟着改。
这条约定就是 2026-10-20 那次重构的原因：以前同一条规则抄在 4 个文件里，已经漂移过两次。

| 规则 | 唯一出处 |
|---|---|
| 工作准则（不看 Token 账单，只看协作效率） | `02_提交与协作规范.md` 开头 |
| push / 授权 / 一次一用 / `--force` | `02_提交与协作规范.md` §02 |
| 提交信息格式与检查清单 | `02_提交与协作规范.md` §03 / §04 |
| 子代理权限来源、配额（默认 3）、申请、用完即评、派活纪律 | `00_子代理与效率.md` |
| AI 的 git 动作清单、子代理零 git | `02_提交与协作规范.md` §02.1 / §02.4 |
| 工程分层与验证 | `01_编程规范/工程架构规范.md` |
| 学习资料的写法边界 | `01_编程规范/学习资料代码规范.md` |
| 接手手册怎么写 | `03_项目接手手册_模板与写法.md` |
| 版本号 | 协作规则版本只在 `02_提交与协作规范.md`；单篇文档可有自己的内容版本（如模板 v2.2、学习资料规范 v1.3），但不得标注协作规则的版本 |
