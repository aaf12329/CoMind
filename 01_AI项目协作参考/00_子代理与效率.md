# 00 · 子代理与效率

> **这一步在开工前做，不是开工后补。**
> 本文件是子代理规则的**唯一出处**；其它文件只引用、不复述。

---

## 0. 所有者原话

> 所有者原话（2026-10-20）：**"我不需要 Token 账单，我只看协作效率。"**
> 林彪式发言，照办。

拆开就是：

- token 数、调用次数、上下文长度**都不是考核项**；
- 考核项是同一个活**用几下干完**——几次往返、几个 Agent、多长时间、返工几次；
- 所以"要不要开子代理"是一个**效率问题**，不是成本问题：
  不开省不下钱，开错了才真的慢。

---

## 1. 🔴 开工前必算：这个活要几个 Agent

AI 在动手前，**必须**在给所有者的"动手说明"里写清这三问的答案：

1. 这个活能不能拆成**互不依赖**的几块？
2. 拆开并行，**真的比串行快**吗？
3. 最快方案要几个 Agent？

结论只能是 **0 到配额之间**（没配过配额就是 0 / 1 / 2 / 3）。
🔴 **0 个也必须写**（连同理由），不允许沉默默认——沉默等于没算。

### 判据表

| 情况 | 建议 | 理由 |
|---|:-:|---|
| 几块活的写盘范围互不相交、可独立完成 | 按块数开 | 真并行，省的是墙钟时间 |
| 有强依赖、必须共享同一份上下文 | **0 个**，主代理串行做 | 拆开要来回同步，比串行更慢 |
| 活很多，但都压在同一批文件上 | **0 个** | 只会互相踩，收口成本翻倍 |
| 需要人类中途拍板 / 有审批环节 | **0 个** | 子代理没有人类回路，问不到所有者 |
| 结论本身就是长文（写规范、写文档） | **0 个** | 所有者还得再读一遍再改，等于付两次 |

---

## 2. 🔴 配额：由所有者配置能开几个（未配置时默认 3）

- **配额由所有者定**：开工时所有者可以直接说「这次最多开 N 个」，N 就是本次任务的配额；
  也可以在一开始就给 Agent 设好，后续任务沿用。
- 🔴 **所有者没配置时，默认 3 个**。AI 不得自己调高配额，也不得把上一次的配额带进这一次。
- 配额管的是**同时在线**的 Agent 数，不是累计数：一批做完、收口、再开下一批，
  仍受同一个配额约束，但不额外申请。
- 🔴 **配额只对当次任务有效**，任务结束即失效；下次重新配置（没配置就回到默认 3）。
- 需要超出配额时**必须申请**，由所有者决定是否临时放宽（放宽也只对当次有效）。

## 3. 三种开法

派子代理是**被鼓励的**——只要真的更快。谁批、怎么批，看你是哪一种：

| 情形 | 谁决定 | 要不要等点头 |
|---|---|---|
| 3.1 人类直接下令 | 所有者 | 不用，AI 照办 |
| **3.2 配额内（默认）** | **AI 自己判断** | **不用，报备即可** |
| 3.3 超配额 | 所有者 | 要，先申请拿到批准 |

全部**一次一用**：这一批开完即失效，下次重新判断（见 `02_提交与协作规范.md` §02）。

### 3.1 · 人类直接下令 🟢

所有者一句话就能开；AI 照办，🔴 **不得增减数量、不得改动职责**。

> 示例：
> 「你开 2 个子智能体，一个去搜索相关网站，一个子智能体去改 BUG，
>  然后主对话跟我对话讨论代码结构与发展方向。」

| 谁 | 干什么 |
|---|---|
| 子代理 1 | 搜索相关网站 |
| 子代理 2 | 改 BUG |
| **主代理** | **不接这两个活**，只跟所有者对话（讨论代码结构与发展方向） |

> 🟡 人类指令里没说的，AI 不要自己补：没说"也去改代码"，主代理就只对话；
> 没说"顺便再查一轮"，子代理就不扩范围。

### 3.2 · 配额内：报备即开（默认路径）🟢

AI 按 §1 算完，只要**不超过配额**，报备之后就可以直接开，**不用等点头**。
这里的"报备"= **先说明再执行**（所有者手册里的定义），说了就算数。

报备必须写清三件事，并附上所有者那句话：

| 必填 | 含义 |
|---|---|
| **开几个** | 打算开几个，**不得超过配额** |
| **用来干什么** | 每个负责什么，附写盘范围与预计耗时 |
| **开启之后有几个 Agent 干活** | 并发总数 = 子代理数 + 主代理是否也动手 |

并且 🔴 **必须原样附上所有者那句话**，让他一眼看到按什么标准算：

> **我不需要 Token 账单，我只看协作效率。**

#### 报备模板（照这个写）

```text
报备：开 2 个子代理（配额 3）。
依据：我不需要 Token 账单，我只看协作效率。
理由：这两块写盘范围不相交，并行比串行少约 15 分钟。

开启之后共 3 个 Agent 干活：2 个子代理 + 我（主代理）继续改 模块C.py 与 模块D.py。

1. 子代理 A —— 搬 HTML 去标签实现｜写范围 src/xxx/模块A.py｜约 10 分钟
2. 子代理 B —— 合并 robots 判定｜写范围 src/xxx/模块B.py｜约 20 分钟

两个写范围不相交；我不碰 A、B 的文件。
```

> 🟡 所有者当场说"先别开"或"少开一个"，立刻按他说的收。
> 🔴 报备必须在**开工之前**发出，不是"先派了再补报备"。

### 3.3 · 超配额：必须申请批准 🔴

超过配额、或所有者为本次任务设了"必须批准"时，走这条：**先申请，拿到批准再动**；
🔴 不批就不派，按 §1 退到配额内（或 0 个）的方案。

🔴 AI 不得擅自扩大数量或改职责——要变，重新报备/申请。

## 4. 🔴 派活纪律（防互相踩，这些坑真踩过）

1. **写盘范围不相交**：派活前先划分，各代理的文件集合**必须没有交集**；
2. **子代理零 git 操作**：`add` / `commit` / `push` / 建分支 / 改 remote 一概不许，
   只交代码，由主代理统一收口（详见 `02_提交与协作规范.md` §02.4）；
3. **主代理验真身**：收口时逐个 `git diff` 看实际改动，**不采信**子代理
   "我做完了 / 已经全绿了"的自述；**全量测试由主代理自己再跑一遍**；
4. **同一时刻只允许一个进程写同一份数据目录**（另一个代理正在跑采集/训练时不要重跑）；
5. **产出必须可复核**：给真实命令输出、文件行数、diff 摘要，而不是只给结论。

---

## 5. 效率三条

- 子代理省的是**主代理的上下文**，不是时间——它的价值在于主代理不必读那堆中间过程；
- **并行度越高，冲突面越大**：能串行就别并行，能两个人干完就别派四个；
- 无论派了多少代理，**最终一致性由主代理负责**——没有"别人做的所以不怪我"。
