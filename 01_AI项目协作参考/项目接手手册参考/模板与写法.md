# 🤲 项目接手手册：模板与写法

**AI HANDOVER MANUAL — TEMPLATE & GUIDE** · v2.1 · 2026-10-08

> **本文件写给两类读者**：要给 AI 写项目手册的人类，以及要接手新项目的 AI。
> 一份好的接手手册 = AI 读完即可按同样的流程与规矩干活：**不重新探索、
> 不重复踩坑、不越权**。
> 本模板由一个真实 CV 训练项目的工作手册蒸馏而来——个人信息已移除，
> 实例均为可跨项目复用的通用教训。**用法：复制 §2 骨架填空，实例抄 §3、§4。**

---

## 0. 什么时候需要写接手手册

出现以下任一情况，就值得花半小时写一份：

- 项目的环境/管线/禁区**一句话说不清**，每次都要口头重新交代；
- 换 AI（或换会话、换机器）就要**重新踩一遍坑**；
- 有**红线**（不许动的目录、不许超的阈值、必须报备的操作）需要硬约束。

---

## 1. 写法三原则 ★

1. **事实前置**：开篇一张"项目事实表"（§2 第 0 节），路径、环境、硬件、交付物
   直接让 AI **采信**，禁止重新探测——AI 最贵的 token 花在重复发现已知事实上。
2. **循环最小化**：把"每个任务必走"的循环压成一行（§2 第 1 节），越短越会被
   严格执行；细节放循环下方的编号解释里。
3. **坑表一行一条**：已知坑写成 `坑 | 一句话对策` 两列表（§2 第 6 节），
   动手前扫一眼即可，不写成段落——没人读长篇警告。

## 1. 核心工作循环 ★（每个任务都必须完整走一遍）

① 先说明 → ② 执行 → ③ 同步文档 → ④ git commit → ⑤ 停（等人类 push）

1. **先说明你要干什么**：目标、要改/建哪些文件、是否触发报备条款。
   禁止不打招呼就开始大动作。
2. **执行**：过程中发现新情况（报错、方案要改、要下载大文件）随时插播说明。
3. **同步文档**：按提交前检查清单更新 README / .gitignore / 指令文档 / 台账——
   代码先行、文档滞后是返工的最大来源。
   若为学习资料：代码文件开头注释函数结构、职责与树状调用关系；
   README 等说明文档画出输入结构与形状、代码结构与调用树，并对应步骤。
   同步函数调用、数据变换和图文说明，不能只更新目录树。
4. **git commit**：注释**中英双语**（中文在前），一个逻辑单元一次提交。
5. **停**：🔴 **push 只由人类执行**；人类授权可推，但**一次授权只能用一次**
   （推完即失效，不延展、不跨仓库/分支、不转授）。详见提交与协作规范 §02。

🔴 **一切授权一次有效**：人类给的每一条授权（push、开子代理、任何超默认权限的操作）
都只用一次——干完即失效，不续用、不延展、不类推、不转授；要再干重新申请。

**如果打算开子代理**：

🔴 **数量与职责由人类定**——人类可以直接用自然语言指定（例："开 2 个子智能体，
一个搜网站、一个改 BUG，主对话继续跟我讨论结构"），AI 照办，**不得增减数量、不得改职责**。

AI 要派必须先申请，申请里写清**三件事**：

| 必填 | 含义 |
|---|---|
| **申请几个** | 打算派几个 |
| **用来干什么** | 每个分别负责什么 |
| **开启之后有几个 Agent 干活** | 并发总数 = 子代理数 + 主代理是否也动手 |

派活的写盘范围必须**互不相交**，子代理**不许碰 git**；
收口时主代理自己 `git diff` 验真身并重跑全量测试。详见提交与协作规范 §11。

🔴 **权限口径（照抄，别改）**：

- **一切授权一次有效**——人类给的每一条授权（push、开子代理、任何超默认操作）只用一次，

## 3. 实例：从真实项目蒸馏的通用坑（可直接搬进你的手册）

以下每条都真实发生过，按"现象 → 通用教训"改写，适配任何 ML/数据/工程项目：

| 坑 | 通用教训 |
|---|---|
| 镜像帧送进模型，左右语义反转 | **增强会改变语义**：镜像/旋转/裁剪动输入前，先审计它对标签含义的影响 |
| 翻转增强开着训"左/右"类，左右标签互相污染 | 含方向/对称敏感类别的模型**禁用对应增强**，需要时用离线"增强+标签互换"副本 |
| 标签符号按文档写，评估全错 | **文档会写错**：符号与坐标约定必须抽样目视验证（曾两度反直觉） |
| 同一受试者跨训练/验证集，指标虚高 | **划分维度 = 防泄漏维度**（按受试者/按会话/按天，不是按图片） |
| 评估代码手打类别字面量，`"open"≠"open_eye"` | 标签一律从**配置文件/标注文件**读取，禁止手打字面量 |
| 过采样只复制标签不复制图片 | 复制样本时**图文必须成对** |
| Windows glob 大小写重复匹配 | `*.mp4`/`*.MP4` 会双匹配——`normcase` 去重 |
| 眼睑参考系测竖直注视无区分度 | **参考系选错，指标无解**：换特征前先想清楚生理/物理依据 |
| RTX 50 系装默认 torch 直接不能用 | 新显卡架构对 CUDA 构建有硬要求，**装环境前先查兼容表** |
| 管道收尾吞报错（exit 0） | 后台命令少用管道收尾，跑完**验证产物存在**再报告成功 |
| `.gitignore` 白名单顺序写反，权重漏提交 | 先 `*.pt` 再 `!models/*.pt`，**后行覆盖前行，顺序不能颠倒** |
| 动了上游/邻接项目目录 | **禁区写成条文**：哪个目录只读、实验只在哪里做，手册里点名 |

## 4. 数据/素材查找通用路径（实证有效的优先级顺序）

1. **Hugging Face API 搜索**（可编程、免费、无账号）：
   `curl "https://huggingface.co/api/datasets?search=关键词&limit=20"`
   用 `downloads` 字段初筛热度，`gated` 字段排查是否要授权；
2. **官方实验室页**：论文里的 "available at" 链接最权威；注意链接会搬家；
3. **Dataverse 归档**（如 darus.uni-stuttgart.de）：API 列文件
   `/api/datasets/:persistentId/?persistentId=doi:...`，
   下载 `/api/access/datafile/:id` —— **HEAD 会 403，必须用 GET**；
4. **Wayback Machine**：老页面死链挖原始直链，再回新服务器试探；
5. **Kaggle / Roboflow Universe**：需免费账号/API key，最后手段。

**新数据接入 SOP**（每次都走，顺序不能乱）：
① 下载前按磁盘规则报备 → ② 校验（zip 完整性/条目数）→
③ **符号与坐标约定抽样目视验证**（文档会写错）→ ④ 转换为目标格式
（**划分维度 = 防泄漏维度**）→ ⑤ 训练/处理 + 配置驱动评估 → ⑥ 文档与台账登记。

## 5. 接手已有项目的 AI 怎么用本模板

1. 先读项目 README 与 `git log` 更新认知，对照手册找**过期信息**；
2. 信息过期时**先请人类 pull / 同步**，确认后再动手，不要凭记忆补全；
3. 发现手册没写的新坑，**干完活顺手补进 §6 坑表**——手册是活的，
   每次踩坑都该让它变厚一点。
