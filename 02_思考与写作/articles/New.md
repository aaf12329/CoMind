# 给刚进大学的你：先做点东西，把 AI 用进学习里

如果让我给刚进大学的同学提一个建议，我会先说：找一件想做的小事，动手把它做出来。

尤其是计算机、电子、电气，以及其他会接触代码的专业。别把准备工作无限延长，也别觉得必须先看完一整套教程，才有资格打开编辑器。做一个能运行、能检查的小东西，比不断收藏路线图更容易让我知道自己究竟缺什么。

这是一份从我自己的学习和项目经历出发的建议。我接触过软件、网页、硬件和算法，也借助 AI 推进过其中不少工作。这里想给新生的，是一个可以开始的入口，以及开始之后怎样继续学下去。

## 先做一个小项目，别把教程当成开工许可证

项目可以很小：把一张表中的记录整理清楚，做一个有按钮和状态变化的网页，或者让开发板按预期读取一次输入。先确定输入是什么、希望得到什么结果，再让 AI 帮忙拆出最小步骤。

一开始做错很正常。把试验放在独立目录或数据副本里，留下能退回去的版本，改坏了就重做。先跑通一条路径，再追问它为什么这样运行，通常能让学习的问题变得具体。

我原稿里说“别去网上找教程”，真正想反对的是一种拖延：一直找最完整、最权威、最适合自己的课程，却迟迟没有开始做事。教程、教材和官方文档仍然有用，尤其当你连报错涉及的概念都不认识时。我的习惯是带着卡点去查，把查到的东西用回当前项目，再看问题是否解决。

同样，先认识手上的机器也有帮助。我会用图吧工具箱这类自己熟悉的工具查看设备情况，但硬件工具箱不等于编程环境。编译器、Python、Node.js 和项目依赖，仍要按你实际做的事情配置。装得多不会自动变成会得多，能解释当前项目需要哪些工具更重要。

## 先给 AI 分工，再决定要不要付费

刚开始接触 AI，不必急着买齐所有会员。先用几个真实任务试一试：让它解释一道题、阅读一份材料、修改一个小程序。观察它在哪些事情上节省时间，哪些回答还需要你反复核对。

别让一个顺手的聊天窗口承包所有任务，也别只把 AI 当成给作业出答案的地方。不同任务可以换入口，重要的是看它究竟帮你完成了哪一步。

按我自己的偏好，代码和数学问题会先交给 DeepSeek 或 GLM 尝试；论文和较长文档，我更愿意让 Kimi 帮忙梳理。这个分工表示我的使用习惯，不是给各家模型排一个适用于所有任务的名次。你也可以把同一道题、同一段材料交给不同工具，比较它们给出的依据和可验证结果。

读论文时，我会要求它指出结论来自哪里、实验条件是什么、哪些解释属于推测，再回到对应原文。Kimi 的官方说明提供了文档处理及研究等功能入口，但有这些功能，不意味着每一条摘要和引用都天然正确。[Kimi 官方概览](https://www.kimi.ai/zh-hans/help/getting-started/overview)

接下来可以认识 Agent。简单理解，它把模型和工具、执行流程连接起来，让 AI 有机会读取项目、改文件、运行命令，再根据结果继续处理。有些还支持浏览器或桌面操作，具体能力与权限取决于工具。对新生而言，值得体验的是这种从“给我一段回答”到“完成一个可检查步骤”的变化。

我原稿里提到的 ZCode 和 WorkBuddy，可以作为了解这类工作方式的入口。工具和模型要分清：ZCode 文档说明了自定义模型服务的接入方式，DeepSeek 官方也提供了接入 WorkBuddy/CodeBuddy 的说明。使用什么工具、背后调用什么模型、额度从哪里扣，是需要分别弄清的几件事。[ZCode：连接模型](https://www.zcode.network/cn/docs/configuration/)；[DeepSeek：接入 WorkBuddy/CodeBuddy](https://api-docs.deepseek.com/zh-cn/quick_start/agent_integrations/workbuddy/)

网页会员、编程套餐和按量计费的 API，也不能默认是同一种权益。API 可以先理解为程序调用模型服务的接口；套餐则要看允许在哪些工具和场景中使用。用量不大时，先比较少量调用的成本；确实经常使用，再考虑合适的订阅。是否付费，应由实际用途和自己能够承担的预算决定。

我确实在一次假期活动中用得很尽兴，推进了表格模型、数据生成、个人 Agent 和网页等方向的练习。但这些是我的阶段性经历，不能变成给所有新生开的进度表。原稿中的月费、赠送 Token 数量和免费活动，也只反映当时的记忆；准备使用时，重新看官方权益和账户里的实际额度。

如果以后任务变复杂，可以尝试让一个模型负责规划和审查，另一个负责初步实现。前提是任务边界清楚，交接内容能核对。一个小练习由一个助手完成就足够时，也不用为了“多 Agent”先搭一套复杂系统。

## 尽早认识 Git，给自己的试错留下退路

我会建议刚开始写代码的同学尽早接触 Git。它是分布式版本控制系统，既用于小项目，也能用于很大的项目，并不只属于中小公司。对个人学习最直接的帮助，是留下每次改动的记录，知道一个能运行的版本长什么样，以及后来改了什么。[Git 官方介绍](https://git-scm.com/)

GitHub 则可以用来托管项目、阅读别人的代码和文档、观察问题讨论与协作。Git 是工具，GitHub 是平台，两者要分开认识。[GitHub 官方入门](https://docs.github.com/en/get-started/start-your-journey/what-is-github)

一开始不用追求掌握所有命令。先会查看改动、保存一次有意义的提交、取回一个项目，再逐渐理解分支和协作。让 AI 帮你操作时，也可以要求它说明这次改了哪些文件、为什么改、怎样验证。

“我让它改过了”和“我知道现在这个版本做了什么”，是两个不同的学习状态。新生可以借助前者起步，也要慢慢走向后者。

## 不同专业，找一个能接上自己问题的入口

如果你走代码相关方向，我个人会推荐把 C 和 Python 当作两个可考虑的起点。C 帮我接触内存、指针和数据布局；Python 让我更快地做数据处理、模型实验和小工具，也能继续学习类与对象。它们是我用过的入口，具体顺序仍要结合课程和项目，不必为了照抄路线而频繁换语言。

之后按想做的事情分叉。想接触 AI，可以从数据、训练、验证和结果评估的小任务开始；想做网页，先把 HTML、CSS、JavaScript 的关系弄清，再接触 TypeScript，以及 React 或 Vue 这样的界面开发工具。Next.js 属于用于构建全栈应用的 React 框架，不能简单当作所有前端框架之后都必须接的一门“后端”。[Next.js 官方说明](https://nextjs.org/docs)

硬件方向则可以从 51 或 STM32 的入门实验出发。原稿提到的江协科技提供了相关教程入口。先完成一次输入、输出或通信，理解接线、程序和实际现象之间的对应，再继续找适合自己的方向。[江协科技：教学视频](https://jiangxiekeji.com/tutorial.html)

如果是生物、化学、环境等方向，我更建议带着本专业的问题去找计算机方向的同学合作。整理文献表、检查实验记录、可视化一组数据，都可能成为共同项目。你需要把变量含义、单位、条件和想回答的问题说清楚，对方则帮助把处理步骤实现出来。AI 可以降低开始沟通的成本，但专业判断仍然要有人负责。

如果是人文社科方向，也可以从文档、资料和表格任务开始。用 Kimi 等工具辅助阅读，用 WorkBuddy 这类工具尝试整理工作；先选一份能检查结果的小材料，看看它如何提取信息、组织内容，再核对有没有漏掉条件或误读上下文。没必要先完成一整套编程课程，才允许自己借用这些工具。

不同专业的新生，没有必要都从同一门语言、同一个软件或同一种模型开始。更值得共同掌握的，是把问题说清楚、拿到一个结果，并判断这个结果是否可靠。

## AI 能帮你做事，判断仍要落到具体依据上

我想给新生举一个来自数据工作的例子。CSV 可以用 Excel 打开，但它本质上是文本形式的表格数据交换格式，不等于带有多个工作表和格式设置的 Excel 工作簿。先认识自己处理的文件，才能知道哪些信息被保存了。[RFC 4180：CSV 格式说明](https://www.rfc-editor.org/rfc/rfc4180)

假设某列记录同类设备的工作电压，多数是 5 V，其中一项写着 220 V，可以先把它标记出来检查。但不能只因为数字相差很大就宣布它错了：还要确认单位、设备型号，以及这一列究竟记录工作电压还是电源输入。模型或规则可以帮助筛出值得核对的记录，判断仍要回到原始信息。

确认一项数据确实错误且无法找回时，才进一步考虑如何处理。这里也要纠正原稿中的一个术语：整列均值填补与 KNN 填补不是同一件事。KNN 会根据可用特征寻找相近样本，再利用邻居在相应特征上的数值估计缺失项。填出来的数仍是估计，不是恢复了一次真实测量。[scikit-learn：缺失值填补](https://scikit-learn.org/stable/modules/impute.html)

我的生物炭环境治理相关研究里，仍有很多工作交给 XGBoost、CatBoost 这类具体方法处理；训练样本不足时，也研究过用 GAN 类方法生成数据。但生成更多记录之后，方案有没有帮助，还需要用留出的真实数据和对照结果检查。AI 可以帮我组织代码与实验，不能把“程序运行完了”自动变成“结论成立”。

新生不必现在就学会这些模型。这个例子想说明的是：会使用工具，可以让你更早碰到一个真正的问题；继续追问数据、假设和证据，才会让这个问题变成自己的知识。

## 前两个月，争取留下几份自己能接着做的东西

如果要把这些建议收成一个起步方向，我希望刚入学的同学先完成几件事：

1. **做出一个小成果。** 输入和预期结果说得清，自己能够运行，知道从哪里开始。
2. **记下一次完整排错。** 什么现象触发了问题，试过什么，最后依据什么认为已经修好。
3. **留下一个能恢复的版本。** 代码、依赖和运行说明放在一起，隔几天回来还能接着做。
4. **看清 AI 实际帮了什么。** 哪一步节省了时间，哪一步经常出错，再据此决定继续学习、换工具或付费。

这里的“两个月”是我设想的观察期，不是规定所有人必须完成多少技术栈。课程安排、基础和设备都不同，重要的是别让学习一直停在搜索入口、比较排名和等待准备好的阶段。

在我看来，AI 值得新生早点接触，是因为它缩短了从陌生信息到一次实际尝试之间的距离。一个术语可以被解释成例子，一段想法可以被拆成步骤，不同专业的人也更容易围绕同一份材料开始协作。这是我从个人经历提出的判断，不意味着知识、机会和资源已经对所有人同样可得。

你可以借 AI 更早动手，也可以借具体问题更快发现自己需要补什么。先做点东西，留下证据，再带着新的问题回来。大学里的第一步，可以从这里开始。
